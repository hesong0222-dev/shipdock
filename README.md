# shipdock

**Package-manager manifests from a GitHub Release, with no config file.**
shipdock reads the files attached to a release, works out which asset is for which OS and CPU, and writes a Homebrew formula, a Scoop manifest and a winget manifest. Then it re-downloads every URL to check the hashes. Zero dependencies.

```text
$ shipdock plan sharkdp/fd

  windows amd64     zip      fd-v10.5.0-x86_64-pc-windows-msvc.zip
  ...
  -                          fd-v10.5.0-i686-pc-windows-msvc.zip  [unsupported arch]

Manager   Status        Uses
Homebrew  ready         darwin-arm64: fd-v10.5.0-aarch64-apple-darwin.tar.gz
                        darwin-amd64: fd-v10.5.0-x86_64-apple-darwin.tar.gz
                        linux-arm64: fd-v10.5.0-aarch64-unknown-linux-gnu.tar.gz
```

When an asset is missing, `plan` says what that costs you, for example
`linux arm64 asset missing → Homebrew formula will have no Hardware::CPU.arm? block in on_linux (found deb, not usable here)`.

## Why

If you publish a CLI as release assets, getting it into Homebrew, Scoop and winget means writing three manifest formats by hand and keeping their URLs and hashes right.
The closest existing tool is the `prebuilt` builder in GoReleaser Pro (paid). It packages binaries you already built, but you configure it in `.goreleaser.yaml`: a `prebuilt.path` template to the binaries on local disk, plus `goos`/`goarch` targets, which have no defaults. It does not read assets from an existing GitHub release.
shipdock starts from the release that is already published. There is nothing to configure: it works from the asset names and what is inside the archives.

## Use

```bash
git clone <this repo> && cd shipdock
node bin/shipdock.mjs plan owner/repo [--tag v1.2.3] [--json]   # what each manager can get
node bin/shipdock.mjs generate owner/repo --out dist/ [--tag v1.2.3]
node bin/shipdock.mjs verify dist/ [--brew]
```

Needs Node 18+. Auth uses `GITHUB_TOKEN` / `GH_TOKEN`, or your `gh` login if you have one (60 requests/hour without a token).

- **plan** sorts every asset by OS (`darwin`/`linux`/`windows`), arch (`amd64`/`arm64`, plus `universal` for macOS) and format (`tar.gz`, `tgz`, `zip`, `deb`, `rpm`, `msi`, `exe`, `dmg`, `pkg`, `AppImage`). It skips checksums, signatures, SBOMs and source archives. Aliases: `aarch64` = `arm64`; `x86_64`/`x64` = `amd64`. 32-bit `arm`/`armv7`/`i686` builds are skipped. When both exist, it prefers glibc over musl and MSVC over MinGW.
- **generate** writes `<name>.rb` (Homebrew), `<name>.json` (Scoop) and `<Owner>.<Repo>.yaml` (winget singleton).
  - Hashes come from the release API's `digest` field. If that field is missing, shipdock downloads the file and hashes it. Files over 300 MB are skipped, with a warning.
  - shipdock opens each tar.gz/zip to find the executable: the one named like the repo, or else the only executable in the archive. If it finds none, it uses the repo name and adds a `# TODO` line at the top of the file.
  - Every file starts with `generated by shipdock; review before submitting`.
- **verify** downloads every URL in the generated files and compares sha256 values. With `--brew`, it creates a temporary local tap (`brew tap-new`), runs `brew audit --strict --formula`, then removes the tap. Nothing is installed.

## Verified on

Run on 2026-10-12 (macOS arm64, Homebrew 7.0.6) against the latest releases, with `generate` followed by `verify --brew`.

| Repo | Release | Assets the formula uses | Executable found | Hashes (`verify`) | `brew audit --strict` |
|---|---|---|---|---|---|
| sharkdp/fd | v10.5.0 | `{aarch64,x86_64}-apple-darwin`, `{aarch64,x86_64}-unknown-linux-gnu` tar.gz | `fd` | 7/7 ok | pass |
| BurntSushi/ripgrep | 15.2.0 | `{aarch64,x86_64}-apple-darwin`, `aarch64-unknown-linux-gnu`, `x86_64-unknown-linux-musl` (no gnu build for x86_64 Linux) | `rg` (repo name is `ripgrep`) | 7/7 ok | pass after fix (see below) |
| junegunn/fzf | v0.74.5 | `darwin_{arm64,amd64}`, `linux_{arm64,amd64}` tar.gz | `fzf` | 7/7 ok | pass |

Problems found on the first run, and fixed:
- **fd:** the audit failed with `version 10.5.0 is redundant with version scanned from URL`. shipdock now leaves out `version` when every URL contains it.
- **ripgrep:** the audit failed with `Description is too long … 84`. shipdock now cuts long descriptions at a clause boundary and adds a `# TODO` line asking you to reword it.

The formulas use `if Hardware::CPU.arm?` / `if Hardware::CPU.intel?` inside `on_macos`/`on_linux`. A variant using `on_arm`/`on_intel` also passed the audit.

An older release with no `digest` field (fd v8.0.0) worked too. Hashes were computed by downloading the files, and `verify` matched them. That release has no arm64 builds, so `plan` reported the formula and the Scoop manifest as `partial`.

**How these drafts differ from the official homebrew-core formulas.** The homebrew-core formulas all build from the source tarball. shipdock installs the upstream prebuilt binary.

| | homebrew-core | shipdock draft |
|---|---|---|
| fd | `cargo install` from the tag's source tarball; installs completions and `fd.1`; `license any_of: ["Apache-2.0", "MIT"]`; real `test do` | prebuilt `fd` only. The tarball's `autocomplete/` and `fd.1` are not installed. License `Apache-2.0` only, because that is what the GitHub API reports. `test do` is just `--version`. |
| ripgrep | built with the `pcre2` feature (`depends_on "pcre2"`); generates completions and the man page | prebuilt `rg` only. Upstream's `complete/` and `doc/rg.1` are not installed. On x86_64 Linux it uses the musl build. |
| fzf | `go build` with version ldflags; also installs `fzf-tmux`, `fzf-preview.sh`, shell integration, the Vim plugin and man pages; caveats text | prebuilt `fzf` only. The release tarball contains nothing else. |

**Scoop and winget: syntax and schema checks only; nothing was actually installed.** This machine has neither Scoop nor winget.
The generated files for all three repos validate against the official schemas: Scoop's `schema.json` and winget's `manifest.singleton.1.6.0` JSON schema, checked with Python `jsonschema`.
Their URLs and hashes were checked with `verify`. None of them has been installed or put through `winget validate` or Scoop's own checks.

## Not covered

Homebrew Casks (`.dmg`/`.pkg` apps), Flatpak/Snap, publishing to apt/yum (deb/rpm) repositories, code signing and notarization, real install tests, and submitting to homebrew-core, Scoop buckets or winget-pkgs.
`plan` prints this list every time.

## Limits (read this)

- **Drafts, not submissions.**
  - Only the executable is installed: no completions, man pages, extra scripts or caveats.
  - `test do` only runs `--version`.
  - The license is whatever the GitHub API reports, so dual licenses can show up as just one.
- **winget gets a single installer.** The singleton schema allows one installer, so shipdock writes x64, or arm64 when there is no x64. Covering both needs multi-file manifests, which shipdock does not write.
- **The asset picker uses file names.** It only knows `amd64` and `arm64`. Unusual names can be skipped as `unsupported arch` or `unknown format`. Formats outside the list above, such as `.tar.xz` and `.7z`, are skipped. Run `plan` first.
- **The executable picker is a heuristic.** Archives with several executables and none named like the repo get a `# TODO` line. For a bare `.exe`, shipdock assumes a portable binary, not an installer.
- **`verify --brew` touches your Homebrew install.**
  - It creates a temporary tap and removes it afterwards.
  - The first `brew audit` run may install Homebrew's own developer gems (RuboCop and others) into Homebrew's vendor directory.
- The CI matrix runs Node 18/20/22. Local testing for v0 was on Node 25 only.
